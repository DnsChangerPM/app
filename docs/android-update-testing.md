# چک‌لیست آپدیت روی دستگاه اندروید

تست‌های Flutter کانال نصب اندروید را mock می‌کنند. این موارد به APK امضاشده و دستگاه/امولاتور واقعی نیاز دارند و نباید اجرای `flutter test` را جایگزین آن‌ها دانست.

## پیش‌نیاز

- دو APK با `applicationId` یکسان (`com.dnschanger.app`)، **کلید امضای یکسان** و شماره/کد نسخهٔ افزایشی بسازید.
- نسخهٔ پایین‌تر باید همین پیاده‌سازی updater را داشته باشد؛ نسخهٔ بالاتر را در یک ریلیز عمومی با تگ `vX.Y.Z` و APK universal منتشر کنید.
- روی حداقل API 24، API 26 (مجوز نصب از منبع ناشناس)، API 33/34 و یک نسخهٔ جدیدتر اندروید بررسی کنید.
- انتشار ریلیز آزمایشی در مخزن اصلی، کاربران واقعی را مجبور به آپدیت می‌کند. برای آزمایش توسعه‌ای از مخزن آزمایشی و مقدار موقت `AppConfig.githubRepo` در build محلی استفاده کنید؛ آن تغییر را به محصول نبرید.

## تنظیمات و DNS

- [ ] در تنظیمات هیچ فیلد Worker URL، آدرس API یا آدرس سرور اشتراک دیده نمی‌شود.
- [ ] در ارتقا از نسخهٔ قدیمی، `config_api_base_url` قدیمی حذف و endpoint زمان build استفاده می‌شود.
- [ ] کانال، گروه و سازنده به سه لینک صحیح تلگرام باز می‌شوند (تلگرام نصب‌شده و مرورگر fallback را بررسی کنید).
- [ ] DNS با IPv4 و IPv6، یک آدرس و دو آدرس ذخیره می‌شود؛ پس از بستن/بازکردن برنامه باقی می‌ماند.
- [ ] دامنه، URL، IPv4 نامعتبر و DNS اصلی خالی خطای فرم می‌دهند.
- [ ] پس از برگشت از تنظیمات، DNS شخصی بلافاصله قابل انتخاب/اتصال است.
- [ ] ویرایش/حذف DNS متصل، اتصال قدیمی را قطع می‌کند؛ انتخاب حذف‌شده به Cloudflare عمومی برمی‌گردد.
- [ ] اعلان VPN و کارت وضعیت، IP اشتراکی را نمایش نمی‌دهند.

## شناسایی و مسدودسازی نسخهٔ قدیمی

- [ ] ریلیز جدید بدون وابستگی به `min_version` پنل شناسایی می‌شود.
- [ ] پیش از پاسخ بررسی اولیه، صفحهٔ اصلی قابل استفاده نیست.
- [ ] در تنظیمات/صفحهٔ اشتراک برنامه را پس‌زمینه و دوباره باز کنید؛ آپدیت جدید کل رابط را می‌پوشاند.
- [ ] Back و gesture برگشت، صفحهٔ اصلی یا تنظیمات را باز نمی‌کنند.
- [ ] بعد از شناسایی آپدیت، برنامه را force-stop و اینترنت را قطع کنید؛ دانلود/خروج همچنان نمایش داده می‌شود.
- [ ] قطع بودن Worker یا محدودیت نرخ GitHub، policy ذخیره‌شده را پاک نمی‌کند.
- [ ] APK قدیمی‌تر از `min_version` یا نسخهٔ kill‌شده پیشنهاد نمی‌شود.
- [ ] نسخهٔ مساوی، قدیمی‌تر، prerelease، draft یا ریلیز بدون APK خودبه‌خود قفل ایجاد نمی‌کند.

## دانلود و نصب

- [ ] «دانلود برنامه» دانلود را داخل برنامه آغاز می‌کند، نه در مرورگر.
- [ ] درصد از ۰ شروع می‌شود؛ ۱۰۰ فقط بعد از ذخیرهٔ کامل فایل نمایش داده می‌شود.
- [ ] اینترنت را وسط دانلود قطع کنید: خطای قابل‌فهم، حذف فایل ناقص و امکان دانلود مجدد وجود دارد.
- [ ] خروج وسط دانلود، task و VPN قدیمی را می‌بندد؛ ورود بعدی همچنان اجباری است.
- [ ] پس از دانلود، نصب‌کننده بدون دکمهٔ اضافی باز می‌شود.
- [ ] در API 26+، اگر مجوز نصب داده نشده، تنظیمات مخصوص همین برنامه باز می‌شود؛ پس از دادن مجوز و برگشت، نصب‌کننده خودکار باز می‌شود.
- [ ] رد مجوز یا لغو نصب، صفحهٔ اجباری را حفظ می‌کند؛ «نصب برنامه» فایل کامل را بدون دانلود دوباره باز می‌کند.
- [ ] فایل با امضای متفاوت، پکیج متفاوت، کد نسخهٔ پایین‌تر یا checksum نامعتبر نصب نمی‌شود و خطای مناسب نمایش می‌یابد.
- [ ] پس از تأیید نصب سیستم، برنامه درجا به‌روزرسانی می‌شود و DNS شخصی/تنظیمات حفظ می‌شوند.
- [ ] اجرای نسخهٔ جدید (حتی آفلاین) از gate قدیمی عبور می‌کند.
- [ ] اگر اندروید در زمان بازبودن تنظیمات مجوز، process را از بین ببرد، ورود مجدد همچنان gate دارد و دانلود/نصب قابل تکرار است.

نصب بی‌تأیید کاربر برای برنامهٔ عادی اندروید امکان‌پذیر نیست. APK با کلید متفاوت نیز نمی‌تواند روی نسخهٔ قبلی آپدیت شود؛ این‌ها محدودیت سیستم‌عامل‌اند، نه خطای دکمهٔ دانلود.
