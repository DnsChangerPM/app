# تست اتصال، اعلان و توقف/ازسرگیری VPN

## رفتار مورد انتظار

- وضعیت «متصل» فقط پس از موفقیت `VpnService.Builder.establish()` و آماده‌شدن I/O تونل اعلام می‌شود؛ موفقیت درخواست شروع سرویس به‌تنهایی اتصال محسوب نمی‌شود.
- اندروید علامت VPN/کلید را برای تونل فعال نمایش می‌دهد. شکل و نمایش آن به نسخهٔ اندروید، پوستهٔ گوشی و تنظیمات نوار وضعیت وابسته است؛ برنامه علامت VPN جعلی رسم نمی‌کند.
- **توقف موقت**: تونل و سوکت‌های UDP/TCP بسته می‌شوند؛ DNS انتخابی دیگر اعمال نمی‌شود. سرویس foreground و اعلان «توقف موقت» با دکمه‌های **ازسرگیری / قطع اتصال** باقی می‌مانند. علامت VPN سیستم در این حالت معمولاً حذف می‌شود.
- **ازسرگیری**: با همان DNSها، پورت‌ها و برنامهٔ هدف، تونل دوباره برقرار می‌شود. اگر اجازهٔ VPN از بین رفته باشد، کاربر به برنامه راهنمایی می‌شود تا اجازهٔ سیستم را دوباره بدهد.
- **قطع اتصال**: تونل، تنظیمات جلسهٔ قابل‌ازسرگیری، سرویس و اعلان اتصال حذف می‌شوند. ورود بعدی به برنامه نیازمند زدن دکمهٔ اتصال است.
- بستن صفحهٔ برنامه/حذف task، اتصال فعال یا توقف‌موقت را قطع نمی‌کند؛ کنترل‌های اعلان باقی می‌مانند، تا زمانی که اندروید سرویس/process را متوقف نکرده باشد.
- برنامه بعد از force-stop، توقف از Task Manager اندروید یا کشته شدن process، بدون درخواست کاربر اتصال را از سر نمی‌گیرد. Always-on خودکار برای این پیاده‌سازی اعلام پشتیبانی نمی‌شود.

## مجوزها و محدودهٔ اتصال

- در اندروید ۱۳+، درخواست `POST_NOTIFICATIONS` و اجازهٔ VPN **به‌ترتیب** نمایش داده می‌شوند، نه هم‌زمان.
- رد اعلان، اجازهٔ VPN را رد نمی‌کند؛ ممکن است تونل کار کند ولی اعلان در کشوی اعلان‌ها دیده نشود. در این حالت صفحهٔ اصلی هشدار و دکمهٔ **فعال کردن اعلان‌ها** دارد.
- تنظیمات → **اعلان وضعیت اتصال** به تنظیمات خود برنامه/کانال اعلان در اندروید می‌رود. انتخاب قبلی کاربر با تعویض ID کانال یا درخواست پی‌درپی دور زده نمی‌شود.
- برای نصب تازه، پیش‌فرض DNS روی همهٔ برنامه‌هاست. انتخاب ذخیره‌شدهٔ قبلی حفظ می‌شود. حالت «اعمال DNS فقط روی یک برنامه» اختیاری است و نام پکیج باید مربوط به برنامهٔ نصب‌شده باشد.
- حالت فقط یک برنامه از allow-list استفاده می‌کند؛ حالت همهٔ برنامه‌ها فقط خود DNS Changer را exclude می‌کند. allow/disallow در یک Builder با هم مخلوط نمی‌شوند.
- سوکت‌های DNS بالادستی همیشه با `VpnService.protect()` از تونل مستثنی می‌شوند تا حلقهٔ DNS ایجاد نشود.

## تست روی دستگاه (انجام آن با تست JVM جایگزین نمی‌شود)

حداقل روی API 24، 26، 33/34 و یک نسخهٔ جدیدتر اندروید بررسی کنید:

- [ ] نصب تمیز: اتصال را بزنید؛ در ۱۳+ ابتدا اجازهٔ اعلان، سپس اجازهٔ VPN نمایش داده شود.
- [ ] پس از اجازه، واقعاً تونل برقرار شود؛ وضعیت «متصل»، علامت VPN سیستم (در صورت نمایش در پوستهٔ گوشی) و اعلان foreground دیده شوند.
- [ ] رد اجازهٔ VPN، خطای روشن بدهد و هرگز «متصل» نمایش ندهد.
- [ ] رد اجازهٔ اعلان، تونل را به‌اشتباه ناموفق اعلام نکند؛ هشدار فعال‌سازی اعلان دیده شود.
- [ ] اعلان را از تنظیمات برنامه و سپس فقط از تنظیمات کانال خاموش/روشن کنید؛ دکمهٔ برنامه به صفحهٔ تنظیمات صحیح برود.
- [ ] از داخل برنامه و از خود اعلان: توقف موقت → ازسرگیری → قطع اتصال را بررسی کنید.
- [ ] توقف موقت علامت VPN را بردارد و اعلان ازسرگیری را نگه دارد؛ قطع کامل اعلان را حذف کند.
- [ ] وقتی برنامه باز است، از نوار اعلان توقف/ازسرگیری بزنید؛ وضعیت داخل برنامه بدون بستن/بازکردن تغییر کند.
- [ ] برنامه را پس‌زمینه کنید، از اعلان توقف بزنید و برگردید؛ وضعیت «توقف موقت» باشد.
- [ ] Wi-Fi را به دادهٔ موبایل و برعکس تغییر دهید؛ بازسازی تونل باعث `stopSelf`، حذف اعلان یا حلقهٔ شروع/توقف نشود.
- [ ] شبکه را هنگام توقف موقت تغییر دهید؛ اتصال نباید خودکار از سر گرفته شود.
- [ ] اتصال را چند دقیقه بی‌ترافیک بگذارید؛ نبود DNS query به‌تنهایی نباید VPN را خاموش/بازسازی کند.
- [ ] VPN دیگری را فعال یا مجوز این VPN را از تنظیمات اندروید لغو کنید؛ این برنامه سریع وضعیت واقعی قطع را نشان دهد.
- [ ] DNS شخصی را هنگام توقف موقت ویرایش یا حذف کنید؛ جلسهٔ قدیمی پاک شود و ازسرگیری با DNS قدیمی ممکن نباشد.
- [ ] در حالت فقط یک برنامه، پکیج ناموجود خطا بدهد و به‌جای آن بی‌صدا تمام برنامه‌ها وارد تونل نشوند.
- [ ] با درگاه DNS دلخواه و IPv6 نیز pause/resume را بررسی کنید؛ آدرس IPv6 با پورت خراب نشود.
- [ ] وقتی مجوز VPN روی صفحه است، اتصال را لغو کنید/آپدیت اجباری فعال شود؛ تأیید دیرهنگام آن مجوز نباید VPN را دوباره شروع کند.
- [ ] بعد از شناسایی آپدیت اجباری، اعلان/جلسهٔ paused نیز حذف شود و دکمهٔ قدیمی ازسرگیری نتواند برنامه را دور بزند.
- [ ] با خطای برقراری تونل یا قطع آن، UI همچنان «متصل» نماند.
- [ ] متن اعلان و وضعیت بومی هیچ IP اشتراکی، آدرس API یا URL ریپو را نمایش ندهند.

## تست‌های خودکار

```bash
flutter pub get
flutter analyze
flutter test
flutter build apk --release
bash android/gradlew -p android testReleaseUnitTest --no-daemon
```

`VpnCoreChecks` همان ۱۷ سناریویی است که با JUnit در Gradle اجرا می‌شود و بدون دستگاه نیز روی JVM قابل اجراست. این سناریوها چرخهٔ اتصال، pause/resume، بازسازی تونل، ترتیب foreground، مدل رویدادها، scope برنامه‌ها و یک تبادل واقعی UDP روی loopback را پوشش می‌دهند. تست‌های Flutter، کانال‌های بومی را mock می‌کنند و وضعیت/دکمه‌ها، اعلان خاموش، رویداد اعلان و برگشت از پس‌زمینه را بررسی می‌کنند.

این تست‌ها به‌تنهایی پنجره‌های مجوز، علامت نوار وضعیت و اعلان واقعی Android/OEM را تأیید نمی‌کنند.
