# 🛡️ DNS Changer — اندروید + پنل ادمین کلودفلر

یک برنامه‌ی **تغییر DNS برای اندروید** با فلاتر که دقیقاً مثل «DNS Changer» های معروف
گوگل‌پلی کار می‌کند، ولی کامل‌تر:

- ✅ بخش **رایگان** با DNS های عمومی (Cloudflare ،Google ،Quad9 ،Shecan ،Electro و…)
- ✅ **DNS شخصی**: ذخیره، ویرایش و حذف پروفایل با DNS اصلی و دوم (IPv4 / IPv6)
- ✅ بخش **اشتراکی (خصوصی)** با **لایسنس** — DNS اشتراک قفل است و فقط دکمه‌ی «فعال‌سازی» می‌آید
- ✅ **پنل ادمین رایگان روی Cloudflare Workers + KV** (بدون هیچ هزینه‌ای)
- ✅ ساخت لایسنس با **محدودیت تعداد دستگاه**، مدت‌زمان، و DNS های دلخواه
- ✅ مشاهده‌ی **لیست دستگاه‌های هر لایسنس** (نام، آی‌دی، آخرین ورود، IP) و حذف دستگاه
- ✅ **به‌روزرسانی اجباری از GitHub Releases**: صفحهٔ **دانلود برنامه / خروج از برنامه** در هر ورود تا زمان نصب نسخهٔ جدید
- ✅ **دانلود داخل برنامه با درصد واقعی ۰ تا ۱۰۰** و باز شدن خودکار نصب‌کنندهٔ اندروید پس از دانلود
- ✅ لینک کانال، گروه و سازنده در تنظیمات؛ آدرس API در رابط کاربری نمایش داده نمی‌شود
- ✅ **انتشار خودکار APK** در بخش Releases گیت‌هاب با GitHub Actions (ازت نسخه می‌پرسد)
- ✅ امکان **تمرکز روی یک برنامه‌ی خاص** (مثل `com.tencent.ig`)
- ✅ اعلان foreground با **توقف موقت / ازسرگیری / قطع اتصال** و نمایش وضعیت واقعی تونل در برنامه

## 📱 سازگاری با اندروید

- **حداقل نسخه: اندروید ۷ (API 24)** — روی اندروید ۷، ۸، ۹، ۱۰، ۱۱، ۱۲، ۱۳، ۱۴، ۱۵ و ۱۶ نصب و اجرا می‌شود.
- `targetSdk 34` (اندروید ۱۴) — روی نسخه‌های جدیدتر هم بدون مشکل اجرا می‌شود.
- سرویس VPN به‌صورت `foreground service` با نوع `specialUse` برای اندروید ۱۴+ ثبت شده و
  درخواست اجازه‌ی اعلان (Android 13+) و اجازهٔ VPN به‌ترتیب انجام می‌شوند؛ در صورت خاموش بودن اعلان‌ها، راهنمای فعال‌سازی در برنامه وجود دارد.
- API های بالاتر از حداقل نسخه (مانند کانال اعلان و نوع foreground service) با `Build.VERSION` یا AndroidX محافظت می‌شوند.

## ۲) انتشار APK با GitHub Actions

1. به تب **Actions** ریپو برو → **Build & Release APK** → **Run workflow**.
2. در فیلد **version** نسخه را بزن (مثلاً `1.2.0`). نسخه باید به شکل `X.Y.Z` باشد.
3. (اختیاری) توضیحات ریلیز را بنویس.
4. Run بزن. بعد از پایان، در بخش **Releases** یک APK آماده‌ی دانلود هست.

### امضای ثابت (برای آپدیت بدون خطا) — مهم!
انتشار عمومی بدون Secret های امضا **متوقف می‌شود**؛ کلید debug موقتِ هر اجرای CI
برای آپدیت روی نسخهٔ قبلی مناسب نیست. تمام ریلیزها باید با **همان کلید امضای نسخهٔ نصب‌شده** ساخته شوند.
برای اولین انتشار:

1. `bash scripts/gen_keystore.sh` را اجرا کن.
2. در ریپو: **Settings → Secrets and variables → Actions** این چهار Secret را اضافه کن:
   - `KEYSTORE_BASE64`
   - `KEYSTORE_PASSWORD`
   - `KEY_ALIAS`
   - `KEY_PASSWORD`

> اگر قبلاً برنامه را منتشر کرده‌اید، **کلید جدید نسازید**؛ همان keystore قبلی را نگه دارید.
> اگر کلید نسخهٔ قدیمی از دست رفته باشد، آپدیت درجا با کلید متفاوت ممکن نیست. حذف و نصب مجدد
> داده‌های محلی را از بین می‌برد و نباید به‌عنوان آپدیت عادی به کاربر تحمیل شود.
> `applicationId` باید ثابت بماند و `versionCode` افزایش پیدا کند. فرمول فعلی
> `major * 10000 + minor * 100 + patch` است؛ minor و patch باید بین ۰ تا ۹۹ باشند.
> build محلی و CI بدون انتشار همچنان می‌توانند از امضای debug استفاده کنند.

## ۳) پنل ادمین روی Cloudflare (رایگان)

```bash
cd cloudflare
npm install
npx wrangler login

# سه KV namespace بساز (ID ها را کپی کن):
npx wrangler kv namespace create LICENSES
npx wrangler kv namespace create DEVICES
npx wrangler kv namespace create CONFIG
```

ID ها را در `cloudflare/wrangler.toml` بگذار، بعد:

```bash
npx wrangler secret put ADMIN_KEY    # کلید ورود به پنل (اختیاری ولی پیشنهادی)
npx wrangler deploy
```

آدرس پنل: `https://dns-changer-admin.xxx.workers.dev/admin`

> راهنمای کامل‌تر: [`cloudflare/README.md`](cloudflare/README.md)

### لینک کردن برنامه به پنل
آدرس Worker فقط در **زمان build** تنظیم می‌شود؛ فیلد Cloudflare API / Worker URL از
تنظیمات کاربر حذف شده و مقدار قدیمی ذخیره‌شده نیز هنگام ارتقا پاک می‌شود:

```bash
flutter build apk --release --dart-define=API_BASE_URL=https://YOUR.workers.dev
```

در GitHub Actions از Secret به نام `API_BASE_URL` استفاده کنید؛ اگر نباشد،
`CLOUDFLARE_WORKER_URL` و سپس پیش‌فرض داخل کد استفاده می‌شود. آدرس در پیام‌های UI چاپ نمی‌شود.

> حذف آدرس از UI به معنی مخفی‌سازی کامل سرور نیست؛ endpoint موردنیاز کلاینت را نمی‌توان
> در برابر بررسی APK یا ترافیک شبکه محرمانه دانست. کنترل دسترسی باید سمت سرور انجام شود.
> آدرس‌های DNS اشتراکی نیز در کارت سرور، وضعیت اتصال و اعلان VPN نمایش داده نمی‌شوند؛
> base64 صرفاً قالب انتقال است و رمزنگاری نیست.

## ۴) ساخت لایسنس و محدودیت دستگاه

در پنل ادمین → تب **Licenses**:

1. نام پلن، **حد دستگاه** (مثلاً ۳)، مدت (روز یا مادام‌العمر) و **DNS های خصوصی** را وارد کن (مثلاً `1.1.1.1, 1.0.0.1`).
2. **Generate license key** را بزن و کلید را برای کاربر بفرست.
3. کاربر در برنامه کلید را می‌زند → لایسنس فعال می‌شود. DNS اشتراک **قفل** است و فقط
   گزینه‌ی «فعال» نشان داده می‌شود (آدرس‌ها در پاسخ API به‌صورت base64 می‌آیند و در UI نمایش داده نمی‌شوند).
4. با زدن دکمه‌ی **Devices** روی هر لایسنس، دستگاه‌های متصل (نام، آی‌دی، زمان، IP) را می‌بینی و می‌توانی هر دستگاه را حذف کنی.

## ۵) آپدیت اجباری و نصب داخل برنامه

1. نسخه‌ای **بالاتر از نسخهٔ فعلی** با تگ `vX.Y.Z` در `DnsChangerPM/app` منتشر کنید.
2. فایل APK **universal / release** را به Assets ریلیز عمومی اضافه کنید (workflow همین کار را می‌کند).
3. برنامه در شروع و هنگام برگشت از پس‌زمینه، GitHub Releases و سیاست پنل را بررسی می‌کند.
   انتشار draft، prerelease یا ریلیز بدون APK آماده باعث قفل شدن خودکار برنامه نمی‌شود.
4. وقتی نسخهٔ جدید شناسایی شد، همهٔ صفحات از جمله تنظیمات با صفحهٔ **دانلود برنامه** و
   دکمهٔ **خروج از برنامه** در زیر آن جایگزین می‌شوند. برگشت یا لغو نصب، نسخهٔ قدیمی را باز نمی‌کند.
5. با دانلود، درصد واقعی **۰ تا ۱۰۰** نمایش داده می‌شود. فایل در cache خصوصی برنامه ذخیره می‌شود؛
   مرورگر باز نمی‌شود و اجازهٔ دسترسی به حافظهٔ عمومی لازم نیست.
6. بعد از دانلود کامل، checksum (اگر GitHub ارائه کند)، نام پکیج، کد نسخه و امضای APK بررسی و
   نصب‌کنندهٔ اندروید باز می‌شود. در اندروید ۸+ ممکن است اجازهٔ **نصب از این منبع** خواسته شود؛
   پس از دادن اجازه، نصب خودکار ادامه پیدا می‌کند تا پنجرهٔ تأیید اندروید نمایش داده شود.
   **تأیید نهایی نصب با کاربر است؛ نصب بی‌اجازه / silent روی دستگاه معمولی ممکن نیست.**
7. در خطای شبکه می‌توان دوباره دانلود کرد. بعد از لغو نصب یا رد مجوز، دکمهٔ **نصب برنامه**
   بدون دانلود دوباره کار می‌کند. خروج حین دانلود آن را متوقف و VPN نسخهٔ قدیمی را قطع می‌کند.

سیاست نسخه، آخرین APK و لینک آن ذخیره می‌شوند؛ پس بعد از شناسایی آپدیت، در هر ورود بعدی
**حتی آفلاین** هم صفحهٔ اجباری باقی می‌ماند. بعد از نصب نسخهٔ جدید، همان cache دیگر نسخهٔ جدید را
مسدود نمی‌کند. اگر هنوز هیچ آپدیتی شناسایی نشده و هر دو منبع در دسترس نباشند، برنامه قابل استفاده
می‌ماند؛ بدون اینترنت نمی‌توان از انتشار یک ریلیز جدید مطلع شد.

### کنترل اضافی از پنل (اختیاری)

بررسی مستقیم GitHub به Secret های پنل وابسته نیست. برای ثبت خودکار `min_version` در پنل،
Secret های `CLOUDFLARE_WORKER_URL` و `ADMIN_KEY` را نیز تنظیم کنید. همچنان می‌توانید در
پنل → **Settings** از **Minimum required version** یا **Killed versions** استفاده کنید.
سیاست پنل نیز آفلاین ذخیره می‌شود. اگر APK مناسبی برای حداقل نسخه موجود نباشد، صفحهٔ اجباری
با امکان تلاش دوباره و خروج نمایش داده می‌شود، نه لینک نسخهٔ قدیمی.

> این رفتار مربوط به نسخه‌های حاوی کد جدید است؛ نسخه‌های قدیمیِ منتشرشده با انتشار این تغییرات
> به‌تنهایی کد جدید دریافت نمی‌کنند. ابتدا این نسخه را با شماره و امضای صحیح منتشر کنید.

## ۶) DNS شخصی و ارتباط با ما

- صفحهٔ اصلی → **+ DNS شخصی** یا تنظیمات → **DNS شخصی**.
- **افزودن DNS شخصی** → نام، DNS اصلی، DNS دوم اختیاری → **ذخیره**.
- IPv4 و IPv6 معتبر پشتیبانی می‌شوند؛ دامنه، لینک DoH و `IP:port` ورودی این فرم نیستند (پورت ۵۳).
- پروفایل ذخیره‌شده را در صفحهٔ اصلی انتخاب و متصل کنید. نام/آدرس‌ها قابل ویرایش‌اند و پروفایل
  قابل حذف است. اگر DNS متصل تغییر یا حذف شود، اتصال قبلی قطع می‌شود تا با تنظیمات جدید دوباره متصل شوید.
- لینک‌های تنظیمات:
  - کانال: [@DnsChangerPM](https://t.me/DnsChangerPM)
  - گروه: [@DnsChangerPMGP](https://t.me/DnsChangerPMGP)
  - سازنده: [@AnishtayiN](https://t.me/AnishtayiN)

## اتصال VPN و کنترل اعلان

- **اتصال** فقط پس از برقراری واقعی تونل «متصل» اعلام می‌شود. اندروید خودش علامت VPN/کلید را مدیریت می‌کند.
- **توقف موقت** تونل را می‌بندد ولی اعلان را با دکمهٔ **ازسرگیری** نگه می‌دارد؛ **قطع اتصال** اعلان و جلسه را کاملاً حذف می‌کند.
- کنترل‌ها هم در صفحهٔ اصلی و هم در اعلان هستند و وضعیت این دو همگام می‌شود.
- اعلان‌های خاموش: صفحهٔ اصلی → **فعال کردن اعلان‌ها** یا تنظیمات → **اعلان وضعیت اتصال**.
- پیش‌فرض نصب تازه روی همهٔ برنامه‌هاست؛ تنظیم قبلی کاربر حفظ می‌شود. حالت فقط یک برنامه اختیاری است و برای پکیج ناموجود خطا نمایش داده می‌شود.
- بازسازی تونل در تغییر شبکه، دیگر سرویس را با `stopSelf()` خاموش نمی‌کند. callback اولیه/تکراری شبکه و بیکاری DNS باعث حلقهٔ اتصال نمی‌شوند.
- [چک‌لیست تست VPN و اعلان روی گوشی](docs/android-vpn-testing.md).

### آیا دانلود داخل برنامه، آدرس‌ها را مخفی می‌کند؟

**خیر.** در پیاده‌سازی فعلی، درخواست‌های GitHub و Cloudflare داخل برنامه انجام می‌شوند و مرورگر باز نمی‌شود؛
اما آدرس‌ها همچنان برای کلاینت قابل دسترسی‌اند. نبود لینک در UI، به معنی محرمانه بودن URL در برابر بررسی APK
یا ترافیکِ خود برنامه نیست. HTTPS نیز جایگزین کنترل دسترسی نیست.

برای حذف URL ریپو از کلاینت باید بررسی نسخه و دانلود APK پشت یک واسطهٔ سمت سرور انجام شود؛ فایل باید از
همان واسطه **stream/proxy** شود، نه اینکه با redirect دوباره به GitHub برود. یک دامنهٔ اختصاصی می‌تواند جای
نام `workers.dev` را بگیرد، ولی آدرس عمومی واسطه باز هم قابل مشاهده است. ریپوی عمومی نیز مستقلاً قابل پیدا کردن است.
**این تغییرِ زیرساختی در نسخهٔ فعلی پیاده‌سازی/استقرار نشده**؛ آدرس، توکن و کنترل دسترسی سمت سرور نباید به اتکای
مخفی بودن URL امن فرض شوند. توکن‌های مدیریتی هیچ‌وقت نباید داخل APK قرار بگیرند.

## ⚙️ نکات فنی

- تونل DNS با `VpnService` اندروید (بدون نیاز به روت) پیاده شده.
- فقط ترافیک DNS (پورت ۵۳) از تونل عبور می‌کند؛ بقیه‌ی ترافیک (مثل سرورهای بازی) مستقیم می‌رود،
  پس بازی مثل `com.tencent.ig` بدون اختلال با DNS انتخابی کار می‌کند.
- برای **تمرکز روی یک برنامه‌ی خاص**: تنظیمات → «اعمال DNS فقط روی یک برنامه» → نام پکیج را بده
  (پیش‌فرض `com.tencent.ig`). با این گزینه فقط DNS همان برنامه از تونل عبور می‌کند.
- اتصال به Worker به‌صورت `https` است؛ اپ در حالت آفلاین از اطلاعات کش‌شده استفاده می‌کند.
